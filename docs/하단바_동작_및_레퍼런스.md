# PickWise 하단 탐색 개선

## 적용 내용

- 홈·탐색·비교·마이에서 세로·가로 스크롤 중에도 하단 바를 유지한다.
- 스크롤 시 바의 높이·위치는 바꾸지 않고 위쪽 구분선만 반응한다.
- 기존 녹색·흰색·회색 테마, 아이콘과 선택 애니메이션을 유지한다.
- 빈 결과나 제품 수와 무관하게 네 탭을 유지한다.
- 화면 키보드가 열릴 때만 기존처럼 숨긴다. 하드웨어 키보드처럼 화면을 차지하지 않으면 유지한다.
- 기본 버튼 영역은 64→56 논리 픽셀이다. 아이콘 24와 라벨 11을 유지한다.
- 글자 크기 2배에서는 버튼 영역이 67로 늘어난다. 동작 줄이기 설정에서는 사용자 지정 전환을 생략한다.
- 가로 화면에서는 실제 좌우 안전영역을 반영한다.

## 아래 여백의 원인과 측정

NavigationBar는 시스템 제스처 영역을 피하기 위해 자체 SafeArea를 사용한다. 기기의 안전영역을 지우거나 임의의 작은 상수로 제한하지 않았다. 상세·가격·추천 화면 바깥의 SafeArea를 정리해 공통 하단 컴포넌트 한곳에서 처리한다.

중첩 SafeArea는 내부 MediaQuery의 패딩을 소비하므로 중첩돼 있다는 이유만으로 항상 여백이 두 배가 되는 것은 아니다. 이번에 34px가 통째로 제거됐다고 주장하지 않는다. 아래 수치는 Flutter 레이아웃 테스트에서 검증한 논리 픽셀 기준이다.

| 하단 시스템 안전영역 | 기존 전체 높이 | 변경 전체 높이 |
| --- | --- | --- |
| 0 | 64 | 56 |
| 16 | 80 | 72 |
| 24 | 88 | 80 |
| 34 | 98 | 90 |

상세 화면의 가격 버튼과 하단 탭 사이 별도 간격도 28→12로 줄였다. 이것은 홈 제스처 안전영역과 별개다. 탭의 실제 터치 영역은 48 이상이며 시스템 안전영역을 침범하지 않는지 확인했다.

## 다른 앱과 비교한 판단

| 자료 | 공식 자료에서 확인한 내용 | PickWise에 대한 판단 |
| --- | --- | --- |
| [Spotify 보관함](https://support.spotify.com/us/article/your-library/) | 모바일의 보관함을 메뉴 바에서 찾도록 안내한다. | 보관한 내용·탐색 등 주요 영역에 바로 접근할 수 있게 한다. |
| [Google Photos 컬렉션](https://support.google.com/photos/answer/6128849?co=GENIE.Platform%3DAndroid&hl=en) | 아래의 컬렉션에서 앨범으로 이동한다. | 비교·마이 같은 주요 목적지의 위치를 안정적으로 유지한다. |
| [Apple TV·Music 사례, WWDC25](https://developer.apple.com/videos/play/wwdc2025/284/) | TV의 스크롤 시 탭 축소, Music의 미니 플레이어 재배치를 설명한다. | 콘텐츠 몰입용 축소 방식을 자주 탭을 오가는 제품 비교에 그대로 적용하지 않는다. |
| [Apple 탭 바 지침](https://developer.apple.com/design/human-interface-guidelines/tab-bars) | 주요 영역 탐색 시 탭 바를 보이게 하고 임시 모달을 예외로 설명한다. | 일반 목록·비교·상세에서는 유지하고, 독립 작업 흐름에서만 숨긴다. |

이는 공식 안내의 탐색 구조를 토대로 한 적용 판단이다. 각 앱의 설치 화면에서 바의 높이나 기종별 패딩을 직접 측정한 비교는 아니다.

## 숨김을 권장하는 상황

| 상황 | 권장 | 현재 상태 |
| --- | --- | --- |
| 홈·탐색·비교·마이 스크롤 | 유지 | 적용 |
| 일반 제품 상세·가격 확인 | 유지 | 적용 |
| 화면 키보드로 검색 | 잠시 숨김 | 기존 동작 유지 |
| 로그인·회원가입·기본 취향 편집 | 작업에 집중하도록 숨김 | 기존 독립 화면 유지 |
| 전체화면 이미지·영상 | 닫기·뒤로가기를 남기고 숨김 | 향후 해당 기능 추가 시 권장 |
| 구매·결제 전용 단계 | 실수로 이탈하지 않도록 숨김 | 향후 해당 기능 추가 시 권장 |

숨김 권장 상황을 모두 새 기능으로 구현한 것은 아니다. 전체화면 뷰어나 결제 기능을 이번에 추가하지 않았다.

## 검증

Flutter 분석 오류 없음. 실제 Docker HTTP 검증을 포함한 전체 테스트 93개 통과. Android APK와 iOS 시뮬레이터용 빌드 성공.

스크롤 고정, 구분선 전환, 탭별 검색어·위치 유지, 빈 결과, 비교 진입, 키보드 복원, 0·16·24·34 안전영역, 최소 터치 크기, 큰 글자, 가로 화면 좌우 안전영역, 상세·가격·추천 화면의 안전영역과 상세 버튼 간격을 확인했다. Device Hub나 시뮬레이터를 직접 제어하지 않았다.
