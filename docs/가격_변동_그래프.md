# 가격 변동 그래프 — 3단계

## 사용 방법

앱을 Hot Restart 또는 재실행한 뒤 제품 상세의 가격 정보 아래 **가격 변동**을 확인한다. 기존 색상·로고·하단 네비게이션은 유지했다. 별도 앱 실행 인자나 서버 주소 변경은 필요 없다.

- **7일·30일·90일**로 조회 기간을 선택한다.
- **자동 조회·수동 입력**을 분리해서 본다. 수동 입력 그래프는 실제 서버 입력 시점 기준이며, 가격을 확인한 날짜는 별도로 표시한다.
- 기간 안에 출처가 여러 개면 **가격 출처**에서 현재·이전 출처를 선택한다. 서로 다른 출처의 가격을 한 선으로 합치지 않는다.
- 그래프를 누르면 가까운 실제 기록의 시각·가격을 확인한다.
- **최근 기록 보기**로 텍스트 목록도 확인할 수 있다. 최근 10개부터 표시하고 10개씩 추가한다.
- **출처 보기**로 선택한 기록의 가격비교 페이지에 이동한다. 배송비·쿠폰 등을 적용한 최종 결제 금액은 해당 판매처에서 확인한다.

기록이 없으면 빈 상태를 표시한다. 한 건이면 점 하나와 ‘첫 기록’ 안내를 표시한다. 0원 또는 임의 과거 가격을 만들어 선을 채우지 않는다. 기록 사이 6시간을 넘는 구간은 선을 연결하지 않는다. 선은 조회 시점의 기록을 읽기 위한 표시이며, 점 사이 가격을 실제로 확인했다는 의미가 아니다.

## 실제 데이터가 쌓이는 방식

자동 수집이 성공하면 현재 제품 가격을 갱신하는 트랜잭션 안에서 가격 이력도 저장한다. 같은 가격이라도 정상 조회했다면 기록을 추가한다. 중복 저장은 제품 ID·버전의 유일 키로 방지한다. 기존 제품별 최소 1시간 수집 간격은 바꾸지 않았다.

외부 조회가 실패하면 이력을 추가하지 않는다. 가격 갱신 후 이력 저장에 실패하는 경우에도 트랜잭션 전체가 취소되어 현재 가격만 바뀌는 상황을 막는다. 관리자 수정으로 버전·출처·자동 갱신 설정이 달라졌다면 이전 수집 응답을 현재 가격이나 이력에 반영하지 않는다.

관리자 상품 등록 또는 가격·가격 출처·가격 확인일 변경은 **수동 입력**으로 기록한다. 이름·사양만 바꾼 경우에는 가격 기록을 추가하지 않는다. 이미 저장된 비교 스냅샷은 수정하지 않는다.

수동 기록의 `observedAt`은 실제 서버 입력 시각이다. 관리자가 과거 확인일을 입력해도 그날 가격을 수집한 것처럼 과거 시각으로 옮겨 그리지 않는다. 입력한 확인일은 `checkedAt`으로 별도 보관한다.

## 기존 값의 보존과 과거 기록의 한계

`V6__product_price_history.sql`은 새 가격 이력 테이블만 추가한다. 기존 V1~V5는 수정하지 않았다.

기존 DB에서 `priceFetchedAt`이 확인되는 마지막 정상 자동 조회 값은 그 실제 조회 시각으로 한 건 보존한다. 과거의 여러 가격을 복원한 것이 아니다. 과거 조회 시각이 없는 수동 JSON 가격은 자동 이력으로 변환하지 않는다. 이번 8080 적용 시 기존 정상 조회 값이 남아 있는 제품 **19개**에서 마지막 관측값 보존을 확인했다.

처음에는 그래프가 점 하나일 수 있다. 서버가 다음 정상 조회를 수행하면 실제 기록이 차례로 추가된다. 전날 밤 동안의 가격 등 기존에 저장하지 않은 기록은 생성하지 않는다.

## API 계약

```http
GET /api/v1/products/{id}/price-history?days=30&kind=automatic
```

| 파라미터 | 동작 |
|---|---|
| `days` | 7·30·90만 지원. 기본 30. 현재 서버 시각에서 해당 일수 전까지 |
| `kind` | `automatic` 또는 `manual`. 기본 `automatic` |
| `source` | 선택 사항. 응답의 sources.key를 전달. 생략하면 현재 제품 출처 |

응답의 `sources`는 현재 출처와 선택 기간·확인 방식에 관측값이 있는 이전 출처를 제공한다. 출처 키는 사이트와 URL 조합으로 만든 SHA-256이다. 다른 판매 옵션이나 출처 URL을 하나의 가격 선으로 합치지 않는다.

`points`는 `id`, `price`, `observedAt`, `checkedAt`을 시간순으로 반환한다. `asOf`는 서버 응답 기준 시각이며 가격 확인 시각과 다르다. 미래 시각의 관측값은 조회 결과에 포함하지 않는다.

응답은 최대 최신 3,000건으로 제한한다. `total`은 선택 기간·출처의 전체 건수이고, 잘린 경우 `truncated=true`다. 앱은 이 경우 최저·최고와 시작 대비 변화도 ‘표시된 기록 기준’이라고 안내한다. 그래프 가로축은 기록 개수가 아닌 실제 시각 간격을 사용한다.

존재하는 제품에 기록이 없으면 200과 빈 points, 없는 제품은 404, 지원하지 않는 기간·확인 방식·출처는 400이다. 이 API는 공개 제품 정보만 조회하며 관리자 계정·비교 기록·세션 토큰을 포함하지 않는다. 상세 스키마는 `backend/openapi.yaml`을 따른다.

## 앱 상태와 접근성

통신 중에는 로딩 상태를 표시한다. 실패하면 다시 불러오기 버튼을 제공한다. 같은 조건으로 받은 이전 응답이 있으면 마지막 응답 기준 시각을 함께 표시하고, 기간·방식·출처를 바꿀 때는 이전 그래프를 비워 다른 조건의 기록처럼 보이지 않게 한다.

요청 번호를 비교해 느리게 도착한 이전 조건의 응답이 현재 그래프를 덮어쓰지 않도록 했다. 제품 또는 출처가 바뀌면 해당 이력을 다시 불러온다. 앱 카탈로그의 제품 버전이 바뀌면 그래프도 갱신한다.

기존 Flutter Canvas로 그래프를 그려 새 패키지를 추가하지 않았다. 스크린리더용 요약과 텍스트 기록 목록을 제공하며, 필터는 좁은 화면·큰 글자에서 줄바꿈한다.

## 검증 결과 — 2026-11-17

- 서버 전체 테스트 **36개 통과**. 실제 MySQL 테스트 DB를 사용했다.
- 가격 갱신·이력 저장 원자성, 동일 가격 재조회 기록, 실패·수정 충돌 시 미기록을 검사했다.
- 자동·수동 및 출처별 분리, 기간 제한, 실제 시각 순서, 빈 이력, 잘못된 질의, 3,000건 제한을 검사했다.
- 기존 관리자 등록·수정·권한 검사·동시 수정 충돌·비교 스냅샷 보존 테스트를 함께 통과했다.
- 가격 그래프·모델 테스트 **8개 통과**. 빈 이력·한 건·동일 가격, 필터, 통신 실패와 재시도, 오래된 응답 무효화, 320px·2배 글자, 텍스트 기록 목록을 확인했다.
- Flutter 전체 테스트 **187개 통과**. 실제 서버 주소가 필요한 테스트 5개는 기본 실행에서 제외된다.
- Flutter 정적 분석 오류 없음. Android 디버그 APK 빌드 성공.
- 별도 8081 Docker API와 테스트 DB에서 실제 HTTP로 수동 이력 생성·가격 수정·출처 변경·자동/수동 분리와 기존 관리자 기능을 검증했다. 이때 생성한 테스트 계정·상품·기록과 임시 컨테이너만 정리했다.
- 배포된 8080 API를 실제 Flutter HTTP 클라이언트와 가격 이력 모델로 읽는 별도 테스트 1개도 통과했다. 계정이나 상품을 변경하지 않는 읽기 전용 검증이다.
- 최종 8080 API 적용 후 기존 MySQL 컨테이너, 계정·상품·비교 기록 수, 관리자 권한, 비교 스냅샷 해시가 유지됨을 대조했다.
- 제품 20개가 유지되고, 실제 마지막 정상 가격이 있는 19개 제품에서 가격·조회 시각에 맞는 이력이 보존됨을 HTTP로 확인했다. 서버 상태는 UP이다.

시뮬레이터 직접 조작은 하지 않았다. Device Hub 확인은 사용자가 진행한다. 커밋·푸시·브랜치 변경은 하지 않았다.

가격 공급 방식 자체의 이용 조건과 한계는 [가격 자동 갱신 문서](가격_자동_갱신.md)를 따른다. 이번 단계는 목표가 알림이나 푸시 기능을 추가하지 않는다.
