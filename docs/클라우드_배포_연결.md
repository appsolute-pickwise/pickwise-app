# PickWise 클라우드 배포와 앱 연결

현재 상태: 배포용 Dockerfile·운영 DB 설정·상태 확인 API를 준비했다. 클라우드 계정과 실제 배포 주소는 아직 없으며 외부 배포 완료 상태가 아니다.

## 계정 연결 후 진행할 작업

Spring Boot와 PostgreSQL을 Railway의 별도 서비스로 배포하는 구성을 제안한다. 기존 Flutter와 백엔드 코드 구조를 유지한다. 프로젝트 생성 전 현재 요금·무료 제공 기간·중지 정책을 확인하고 사용할 비용 범위를 결정한다.

1. Railway 계정을 만들고 로그인한다. 비밀번호·토큰을 채팅에 보내지 않는다.
2. PickWise 전용 프로젝트와 영구 PostgreSQL 서비스를 만든다. 기존 mini-board Supabase 프로젝트는 사용하지 않는다.
3. API 서비스의 소스 루트는 `backend`로 설정하고 Dockerfile로 빌드한다.
4. `PICKWISE_DB_URL=jdbc:postgresql://<DB호스트>:<포트>/<DB명>`, `PICKWISE_DB_USER`, `PICKWISE_DB_PASSWORD`를 호스팅의 비밀 환경 변수로 설정한다. SSL 설정은 DB 제공자의 연결 안내에 따른다.
5. Java 프로세스는 Railway가 제공하는 `PORT`로 수신한다. 공개 HTTPS 도메인을 발급하고 `/health` 응답과 DB 마이그레이션을 확인한다.
6. 외부 HTTPS 주소에서 제품 조회·가입·로그인·비교 저장·권한 검사를 수행한다.
7. 검증된 실제 주소를 앱의 배포 설정에 반영한다. 존재하지 않는 주소를 미리 앱 기본값으로 넣지 않는다.

## 배포 완료 판정

- Mac의 로컬 서버를 종료해도 외부 HTTPS API가 응답한다.
- 앱에서 사용자가 서버 주소를 입력하지 않아도 배포 서버를 사용한다.
- 서버 재배포 뒤 제품과 사용자 비교 기록이 유지된다.
- 두 계정의 데이터가 분리되고 로그인·로그아웃·만료가 정상 동작한다.
- 기기 네트워크를 바꿔도 접속할 수 있다. 네트워크 장애는 별도 재시도 화면으로 처리한다.

Docker 이미지는 테스트 DB 없이 빌드하기 위해 패키징 단계에서 테스트를 생략한다. 배포 전 별도의 PostgreSQL 테스트 DB에서 `./mvnw test`를 통과시켜야 한다. 이미지 빌드 성공만으로 테스트 성공을 주장하지 않는다.

공개 운영 전에는 기존 개발 인증의 로그인 요청 제한·이메일 확인·비밀번호 복구 등 남은 항목을 점검한다. 현재 구현과 검증 범위는 `백엔드_2-5단계_구현_검증.md`에 기록돼 있다.
