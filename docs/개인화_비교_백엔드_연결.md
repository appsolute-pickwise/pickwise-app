# PickWise 개인화·비교·기본 백엔드 연결

2026-11-15 구현 및 검증 기준이다. 기존 색상·로고와 Provider 구조를 유지했다. 이 문서는 이번 작업의 전체 동작과 검증 범위를 설명한다.

## 1. 실행 방법

현재 개발 환경의 Docker에 Spring Boot와 MySQL이 실행돼 있다. Android Studio에서 `lib/main.dart`를 일반 Run하면 된다. 별도의 실행 인자가 필요 없다.

| 환경 | 자동 선택 주소 |
| --- | --- |
| iOS 시뮬레이터 | `http://localhost:8080` |
| Android 에뮬레이터 | `http://10.0.2.2:8080` |

직접 주소를 바꿀 때만 `--dart-define=PICKWISE_API_URL=...`를 사용한다. `.run`의 `PickWise - Docker Backend`도 추가 인자를 사용하지 않는다.

Docker가 꺼져 있다면 프로젝트 루트에서 실행한다.

```bash
docker compose -f backend/compose.yaml --env-file backend/.env up -d --build
```

앱이 Docker를 실행하지는 않는다. 기존 `.env`와 MySQL 볼륨을 사용하며 `down -v`는 실행하지 않는다. 실기기·클라우드 배포는 이번 범위가 아니다. Android에서는 디버그 빌드에만 로컬 HTTP를 허용했다.

## 2. 데이터 연결과 장애 처리

일반 실행은 항상 서버 제품 API를 사용한다. 서버 주소 미지정 시 내장 JSON으로 대신 동작하던 분기를 제거했다. `AssetProductRepository`는 오프라인 단위·화면 테스트가 데이터를 명시적으로 주입할 때만 사용한다.

제품 목록의 모든 페이지가 정상 수신되고 Product 변환에 성공하면 서버 주소별 마지막 응답과 수신 시점을 캐시한다. 연결 실패·시간 초과·5xx에는 이 캐시를 사용한다. 캐시가 없으면 오류와 재시도를 표시한다. 정상 빈 목록·잘못된 JSON 계약을 서버 장애인 것처럼 숨기지 않는다.

가격 확인일은 가격을 조사한 날짜이고 데이터 수신 시점은 앱이 서버 응답을 받은 시점이다. 서버를 방금 조회했어도 제품 가격이 실시간으로 갱신된 것은 아니다. 상세·비교·가격 화면에서 수신 시점을 구분하고 가격 화면에는 수동 확인 가격임을 표시한다.

## 3. 공정한 추천 계산

추천 규칙 버전은 `2026-11-fair-v1`이다. `ProductPreferences`가 필터·순위·추천 이유·비교 설명의 기준을 공유한다.

1. 예산·착용 형태·ANC 필수·최대 무게 조건을 먼저 적용한다.
2. 선택한 기준 중 정보가 없거나 선택한 배터리 측정 조건이 없는 제품은 참고 후보로 분리한다. 정보가 없다는 이유로 0점을 주지 않는다.
3. 배터리는 이어버드 기준이다. 기본은 `ANC 켬`, 사용자가 `일반 재생`으로 바꿀 수 있다. 다른 조건의 수치를 대신 넣지 않는다. ANC 미지원 제품의 ANC 켬 수치는 순위 계산에 사용하지 않는다.
4. 배터리와 무게만 고정 범위로 계산하고 사용자 중요도로 가중 평균한다.
5. 계산할 수치 기준이 없거나 동점이면 가격 오름차순, 제품 ID 순으로 정렬한다. 화면에 이 이유를 표시한다.

| 수치 기준 | 고정 범위 계산 |
| --- | --- |
| 이어버드 재생 시간 | `시간 / 12`, 0~1 제한 |
| 이어버드 한 쪽 무게 | `(12 - 무게) / 10`, 0~1 제한 |
| 최종 점수 | 계산 가능한 기준의 `값 × 중요도` 합 / 해당 중요도 합 |

이는 기존 프로젝트의 고정 범위를 명시한 규칙이며 시장 전체 성능 백분위라는 의미가 아니다. 후보가 2개뿐이어도 min-max 방식처럼 자동으로 0점·100점으로 벌어지지 않는다. 범위 변경 시 규칙 버전과 테스트도 함께 갱신해야 한다.

ANC는 지원 여부이고 차음 성능 점수가 아니다. 방수는 등급·사용 조건이며 등급의 마지막 숫자를 나눠 성능 점수로 사용하지 않는다. 등록 가격 비교도 각 제품의 가격 확인일 기준으로 설명한다.

## 4. 후보 탐색과 조건 완화

순위 후보와 참고 후보를 각각 3개씩 표시한다. 각각의 더 보기 버튼으로 3개씩 추가한다. 기준이나 로그인 계정이 바뀌면 표시 개수를 초기화한다.

조건에 맞는 후보가 전혀 없으면 예산·최대 무게·착용 형태·ANC 필수 중 하나만 해제한 결과를 각각 계산한다. 실제 후보가 생기는 제안만 변경 내용과 후보 수를 표시한다. 후보 수 내림차순이며 동률은 예산→무게→착용 형태→ANC 순이다.

제안은 버튼을 누르기 전에는 적용되지 않는다. 적용 후 되돌리기로 바로 이전 조건을 복원한다. 중요도와 배터리 조건 변경도 같은 추천 계산을 사용한다.

## 5. 선택 기준 중심 비교표

가격은 항상 첫 행이다. 선택한 기준은 중요도순으로 먼저 보여주며 동률은 선택 순서를 유지한다. 기준을 고르지 않았다면 가격·배터리·무게·ANC·방수가 기본이다. 나머지 항목은 전체 사양 보기로 펼친다.

배터리 행은 추천에서 선택한 조건의 이어버드 값만 사용한다. 미확인 수치를 다른 재생 조건·케이스 포함 시간으로 대신 채우지 않는다. 비교 설명에서도 같은 조건의 값이 누락되면 배터리 우열을 판단하지 않는다.

제품별 상세·가격 보기와 최대 3개 선택은 유지했다. 첫 번째 제품만 열던 화면 하단의 큰 상세 버튼은 제거했다.

## 6. 앱 전체 로그인과 기본 취향

`main.dart`에서 생성한 API를 제품 저장소와 루트 `SessionProvider`가 공유한다. 로그인 화면이 닫혀도 세션은 유지되고 홈에 계정 이메일이 표시된다.

- 접근 토큰은 15분, 갱신 세션은 최초 로그인부터 30일이다.
- 갱신할 때 접근·갱신 토큰을 모두 새로 발급하고 이전 토큰을 폐기한다. 최초 30일 만료일은 연장하지 않는다.
- 서버 DB에는 두 토큰의 SHA-256 해시만 저장한다. 비밀번호는 기존 salt + PBKDF2 해시 방식이며 앱에 저장하지 않는다.
- 앱은 `flutter_secure_storage` 11.2.0을 통해 토큰과 복원에 필요한 계정 식별 정보를 보안 저장소에 보관한다. SharedPreferences에 토큰을 넣지 않는다.
- 동시에 여러 요청이 401을 받아도 갱신은 한 번만 수행한다. GET은 성공적인 갱신 뒤 한 번 재시도한다. 저장·수정·삭제는 자동 재전송하지 않으며 상태 확인 후 사용자가 다시 시도한다.
- 갱신이 실패하면 로컬 세션을 정리하고 재로그인을 안내한다. 로그아웃 시 서버 접근·갱신 세션도 삭제한다. 네트워크 장애로 서버 폐기를 확인하지 못했다면 로컬 로그아웃과 구분해 오류를 안내한다.
- 세션 세대 번호로 이전 계정의 지연 응답을 거부한다. 로그아웃·계정 전환 때 선택 목록과 기록 화면을 비우고, 열려 있던 저장 기록도 더 이상 표시하지 않는다.
- 게스트 취향과 계정별 편집 취향은 서로 다른 키로 보관한다. 로그인 후 서버 기본 취향을 조회하지만 현재 편집 중인 기준을 자동으로 덮지 않는다.
- 저장한 비교 화면의 현재 기준을 기본 취향으로 저장 / 기본 취향 불러오기 버튼으로 명시적으로 저장·복원할 수 있다.
- 30일 만료는 오프라인에서도 확인하고 만료 세션을 정리한다. 오프라인 재실행에서는 보안 저장소의 유효 기간 내 기존 계정과 계정별 취향을 유지하고 연결 오류를 안내한다. 로그인 상태 다시 확인으로 재접속 확인을 시도할 수 있다. 서버 기록을 다른 계정의 캐시로 대신 보여주지 않는다.

보안 저장소 패키지는 기존 의존성에 없던 OS 보안 저장 기능을 위해 추가했다. 패키지의 [공식 설치·플랫폼 설명](https://pub.dev/packages/flutter_secure_storage)에 맞춰 iOS entitlements와 Android 백업 설정을 반영했다.

## 7. 저장 당시와 현재 정보

비교 생성·명시적 덮어쓰기 시 서버가 제품 카탈로그를 직접 조회해 다음 스냅샷을 만든다. 클라이언트가 보낸 임의의 가격을 저장 당시 가격으로 신뢰하지 않는다.

- 제품명·브랜드·제품 ID·가격·가격 출처·가격 확인일
- 주요 사양·단위·사양 출처·사양 확인일
- 선택 기준과 배터리 측정 조건
- 추천 규칙 버전과 서버 저장 시각

기록을 열면 저장 당시 가격·사양·출처와 현재 카탈로그 가격을 구분한다. 현재 정보는 현재 앱이 받은 카탈로그를 의미하며 실시간 판매가를 뜻하지 않는다. 현재 정보로 다시 비교는 현재 제품과 저장된 선택 기준만 편집 목록에 가져오며 원본 서버 기록을 수정하지 않는다. 덮어쓰기 아이콘은 별도의 명시적 수정이고 버전 충돌 시 409를 반환한다.

스냅샷 도입 전 기록은 `snapshot: null`로 유지하며 저장 당시 정보 없음으로 표시한다. 과거 가격·사양을 추정하지 않는다.

## 8. 서버 계약과 마이그레이션

전체 요청·응답 계약은 `backend/openapi.yaml`에 있다. YAML 파싱과 내부 `$ref` 연결을 검사했다.

| API | 동작 |
| --- | --- |
| POST `/api/v1/auth/register` | 회원가입 및 토큰 발급 |
| POST `/api/v1/auth/login` | 로그인 및 토큰 발급 |
| GET `/api/v1/auth/me` | 현재 계정 확인 |
| POST `/api/v1/auth/refresh` | 갱신 토큰 한 번 사용 및 회전 |
| POST `/api/v1/auth/logout` | 해당 세션의 접근·갱신 권한 폐기 |
| GET·PUT `/api/v1/me/preferences` | 계정별 기본 취향 조회·저장 |
| GET·POST `/api/v1/me/comparisons` | 본인 기록 조회·스냅샷 생성 |
| PUT·DELETE `/api/v1/me/comparisons/{id}` | 본인 기록 명시적 수정·삭제 |
| GET `/api/v1/products`·`/{id}` | 제품 목록·상세 |

로그인 응답은 `accessToken`, `refreshToken`, `expiresAt`, `refreshExpiresAt`을 반환한다. 기존 테스트·호출 호환을 위해 `token`을 접근 토큰의 별칭으로 유지했다.

V3는 갱신 해시·만료 시점, 기본 취향 테이블, 비교 스냅샷 열을 추가한다. 기존 로그인 세션만 제거하여 최초 한 번 재로그인하게 한다. 계정·제품·비교 기록과 MySQL 볼륨은 보존한다. 적용된 V1·V2는 수정하지 않았다.

입력 검증 실패가 비밀번호 원문을 기본 경고 로그에 남기지 않도록 검증 예외를 일반 오류 응답으로 처리했다.

| Flutter 정적 분석 | `flutter analyze`: No issues found |

주요 재발 방지 테스트는 누락값·재생 조건·ANC 비점수화, 조건 완화의 독립성·정렬·되돌리기, 3개씩 더 보기, 선택 기준 행·사양 펼치기, 동시 401 갱신, 저장 자동 재전송 금지, 재실행·오프라인 계정 복원, 게스트/계정 취향 분리, 지연된 취향·기록·이전 계정의 갱신 실패 응답 무효화, 스냅샷 불변성과 기존 기록 표시다.

서버 테스트는 전용 `pickwise_test` DB를 사용한다. HTTP 테스트는 개발 서버에 임시 테스트 계정을 생성하며 생성한 비교 기록은 테스트에서 삭제한다. 기존 사용자 계정을 변경하지 않는다.

```bash
flutter analyze
flutter test --dart-define=LIVE_API_URL=http://localhost:8080
flutter build apk --debug
flutter build ios --simulator --debug
```

`LIVE_API_URL`은 실제 HTTP 테스트를 켜는 테스트 전용 옵션이다. 앱 실행 설정인 `PICKWISE_API_URL`과 다르다. 앱 일반 Run에는 어느 옵션도 필요 없다.

## 10. 직접 확인할 항목

Device Hub 또는 시뮬레이터를 직접 조작하지 않았다. 화면 테스트·실제 HTTP·플랫폼 컴파일과 OS 위에서의 실제 실행은 구분한다. 특히 Keychain/Android 보안 저장소의 기기 재실행 후 실제 보관 동작은 아래 절차로 확인해야 한다.

1. Docker가 실행 중인 상태에서 Android Studio의 main.dart를 일반 Run한다.
2. 홈의 로그인 버튼에서 가입·로그인하고 화면을 닫아 홈 계정 표시를 확인한다.
3. 기준을 고르고 기본 취향으로 저장한 다음 제품을 1~3개 담아 비교를 저장한다.
4. 앱을 완전히 종료했다가 다시 Run하여 계정·기본 취향·저장한 비교 조회를 확인한다.
5. 배터리 조건 변경, 참고 후보·더 보기, 빈 결과의 조건 완화·되돌리기를 확인한다.
6. 저장 기록을 열어 저장 당시/현재 정보, 다시 비교 후 원본 보존을 확인한다.
7. 로그아웃하고 다른 계정으로 로그인하여 이전 계정 기록과 선택 목록이 남지 않는지 확인한다.

실제 컨테이너를 중지시키는 장애 실험은 하지 않았다. 연결 실패·5xx·캐시 복원·동시성·지연 응답은 제어 가능한 HTTP 테스트로 검증했다. 클라우드 배포, 실기기 네트워크 연결, 실시간 쇼핑 가격 공급원은 이번 구현에 포함되지 않는다.

## 11. 첫 실행 인증 화면 변경

저장된 세션 복원을 먼저 기다린다. 세션이 없으면 기존 로고가 있는 로그인 화면이 앱 첫 화면이다. 로그인에 성공하면 홈으로 이동하고 유효한 기존 세션은 로그인 화면을 거치지 않는다. 게스트 이용은 로그인 없이 둘러보기로 유지한다.

회원가입은 별도 `SignUpScreen` 경로다. 이메일·비밀번호·비밀번호 확인을 입력하고 가입 성공 시 자동 로그인하여 홈으로 이동한다. 두 인증 화면 모두 기존 `assets/images/logo/pickwiselogo.png`를 그대로 사용한다. 비밀번호는 8~128자만 검사하며 문자 종류 조건을 추가하지 않았다.

저장한 비교 화면에서 인증이 필요한 경우에도 동일한 로그인·회원가입 화면을 사용한다. 중복 요청과 처리 중 화면 전환을 막고, 실패 시 입력과 오류 안내를 유지한다. 작은 화면·확대 글자·키보드 상태는 위젯 테스트로 확인했다.

## 12. 마이페이지

하단 탐색에 마이 탭을 추가했다. 기존 홈·탐색·비교의 인덱스를 유지했다. 하단 바는 후속 개선에서 기본 56px 고정으로 변경했다. 홈의 계정 버튼도 마이페이지로 연결한다.

마이페이지에서는 계정 이메일 또는 게스트 상태, 현재 비교 제품 수, 기본 취향, 저장한 비교, 앱 정보와 로그아웃을 사용할 수 있다. 허구의 주문·포인트·배송·알림 메뉴는 추가하지 않았다. 로그아웃은 확인 후 실행하며 저장 기록은 계정에 남는다.

기본 취향 수정은 기존 기준 선택 화면의 전용 저장 모드다. 로그인한 사용자는 서버 기본 취향을 수정하고 현재 편집 중인 비교와 기준을 유지한다. 게스트는 별도 로컬 키에 저장한다. 저장 실패 시 입력을 유지하고 재시도할 수 있다. 색상과 로고 파일은 유지했다.

자세한 디자인 출처와 구성은 `마이페이지_디자인_및_동작.md`를 참고한다.

## 13. 하단 탐색 고정과 안전영역

스크롤 방향에 따라 바를 숨기던 로직을 제거했다. 홈·탐색·비교·마이에서는 하단 바가 고정되고 스크롤한 탭의 위쪽 구분선만 반응한다. 화면 키보드가 열린 동안에는 기존처럼 숨기며 닫으면 복원한다.

버튼 영역 기본 높이는 64→56 논리 픽셀이다. 큰 글자에서는 높이를 추가하고 기기의 실제 안전영역을 보존한다. 안전영역 34인 조건에서 전체 높이는 98→90이다. 상세·가격·추천 화면의 안전영역 처리를 하단 공통 컴포넌트로 모으고 상세의 버튼-탭 사이 간격은 28→12로 줄였다.

비교 자료와 숨김 권장 상황은 `하단바_동작_및_레퍼런스.md`에 정리했다. 전체 Flutter 테스트 93개와 Android·iOS 빌드를 통과했다.

## 14. 실서비스 준비

비밀번호 변경, 전체 세션 폐기, 운영 요청 제한, 별도 운영 Compose와 HTTPS 프록시, 백업·격리 복구 검사, CI 설정을 추가했다. 공개 배포는 실행하지 않았다. 상세 실행 조건·검증 경계·공개 전 남은 작업은 `실서비스_준비_구현_및_운영.md`를 따른다.
