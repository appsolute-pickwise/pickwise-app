# 백엔드 2~5단계 구현과 검증

> 현재 실행 환경은 Docker Compose의 Spring Boot + MySQL 8.4로 변경됐다. 아래 PostgreSQL 검증 내용은 이전 단계의 기록이며, 현재 실행법은 `../backend/README.md`를 따른다. MySQL에서 서버 통합 테스트 11개를 별도로 통과했다. PostgreSQL 계정·기록은 MySQL로 자동 이전하지 않았다.

## 실행 방법

1. `backend/README.md`에 따라 기존 `.env`를 사용한다. Docker Compose가 MySQL을 실행한다.
2. `cd backend && docker compose up -d --build`로 Spring Boot와 MySQL을 실행한다.
3. Android Studio에서 `lib/main.dart`를 일반 실행한다. 명령줄에서는 `flutter run`만 사용한다. 서버 주소를 명시적으로 변경할 때만 `PICKWISE_API_URL`을 지정한다.
4. 제품 비교 화면 우측의 저장 아이콘으로 로그인·회원가입·저장·복원·수정·삭제를 사용한다.

주소를 지정하지 않아도 Docker 백엔드로 연결한다. 내장 JSON은 테스트 픽스처에서만 명시적으로 사용한다. iOS 시뮬레이터의 개발 서버는 `http://localhost:8080`, Android 에뮬레이터의 호스트는 보통 `http://10.0.2.2:8080`이다. 플랫폼의 개발용 HTTP 허용 설정이 필요할 수 있다. 운영에서는 HTTPS를 사용한다. 이번에는 디바이스 설정이나 시뮬레이터를 조작하지 않았다.

## 구현한 동작

- `http` 1.6.0을 직접 의존성으로 추가했다. Provider는 유지했다.
- 서버 목록의 모든 페이지를 받아 기존 Product 모델로 변환한다. 사양·가격·출처는 서버 DB의 값을 사용하며 이미지는 기존 앱 자산을 사용한다.
- 연결 실패·5xx에서는 서버 주소별 마지막 정상 제품 데이터를 복원하고 수신 시점과 재시도를 표시한다. 정상 빈 목록과 계약 파싱 오류는 장애 캐시로 숨기지 않는다.
- 이메일·비밀번호 회원가입과 로그인, 15분 접근 세션과 30일 갱신 세션, 로그아웃 시 서버 세션 폐기를 구현했다.
- 비밀번호는 무작위 salt와 PBKDF2-HMAC-SHA256 600,000회로 해시한다. 세션 토큰은 32바이트 난수이며 DB에는 SHA-256 해시만 저장한다.
- 앱 루트에서 로그인 상태를 공유하고 토큰을 OS 보안 저장소에 보관한다. 화면 이동·앱 재실행 후에도 세션을 복원한다. 비밀번호와 토큰을 SharedPreferences에 저장하지 않는다.
- 비교 제품 ID 1~3개와 기준을 DB에 저장한다. 기록을 누르면 현재 카탈로그에서 제품과 선택 기준을 복원한다.
- 수정 아이콘은 현재 비교·이름으로 기존 기록을 교체한다. 이전 버전을 보내면 409를 반환한다. 입력 내용은 실패 시 유지되며 새로고침 후 다시 수정할 수 있다.
- 모든 비교 접근에서 서버가 세션 소유자를 확인한다. 타인 기록 수정·삭제는 404, 미인증·만료 토큰은 401이다.
- 비교 생성·수정은 트랜잭션으로 처리한다. 중복·없는 제품·다른 카테고리·제품 수·가중치·기준 값 타입을 검사한다.

## 인증·비교 API

인증 요청은 JSON `{ "email": "...", "password": "..." }`이다. 비밀번호는 8~128자다.

| 메서드·경로 | 동작 | 성공 |
| --- | --- | --- |
| POST /api/v1/auth/register | 회원가입 후 token 반환 | 201 |
| POST /api/v1/auth/login | token 반환 | 200 |
| POST /api/v1/auth/logout | Bearer 세션 폐기 | 204 |
| GET /api/v1/me/comparisons | 본인 최근 기록 최대 100개 | 200 |
| POST /api/v1/me/comparisons | 비교 생성 | 201 |
| PUT /api/v1/me/comparisons/{id} | 버전 검사 후 교체 | 200 |
| DELETE /api/v1/me/comparisons/{id} | 본인 기록 삭제 | 204 |

비교 요청 예시:

```json
{
  "title": "통학용 비교",
  "productIds": ["sony-wf-1000xm5"],
  "preferences": {
    "priorities": ["ANC"],
    "weights": {"ANC": 3},
    "requireAnc": true
  },
  "version": 0
}
```

수정 응답은 `{ "id": "...", "version": 1 }`이다. 같은 0 버전으로 다시 수정하면 409다. 사용자 ID는 요청 본문에서 받지 않는다.

## 수행한 검증

- 실제 PostgreSQL 17의 별도 테스트 DB에서 서버 통합 테스트 7개 통과: 제품 4개, 인증·비교 3개.
- Flutter 전체 테스트 55개 통과, 정적 분석 오류 없음.
- 실제 서버 전용 Flutter 테스트 1개 별도 통과: 제품 조회·회원가입·비교 저장·로그아웃·재로그인·복원·삭제.
- `flutter build apk --debug --no-pub` 성공. Android SDK XML 버전 경고가 있으나 빌드는 성공했다.
- 운영 서버 배포·실기기 UI·iOS 빌드는 확인하지 않았다. 위젯 테스트만으로 실제 기기 UI까지 검증했다고 해석하지 않는다.

실제 서버 테스트는 전용 로컬 DB에서 다음과 같이 실행한다. 테스트 계정이 생성되므로 운영 서버에는 실행하지 않는다.

```bash
flutter test --dart-define=LIVE_API_URL=http://127.0.0.1:8080 test/live_backend_test.dart
```

## 남은 제한

- 공개 인터넷 배포 전 이메일 인증·비밀번호 복구·인증 요청 속도 제한·계정 삭제·개인정보 처리·운영 모니터링을 보완해야 한다. 현재는 로컬 개발·검증 단계다.
- 로그인 지속·갱신 토큰·자동 재로그인은 구현하지 않았다. 401에서 토큰을 비우고 재로그인을 요청한다.
- 기록에 제품 ID와 조건을 저장하며, 과거 가격·사양 전체의 스냅샷을 저장하지 않는다. 복원 시 현재 제품 정보로 비교한다.
- 원격 카탈로그에는 별도 관리자 수정 API가 없다. 제품 수정은 DB에서 관리한다.
- 목록은 최대 최근 100개이며 기록 목록 페이지 UI는 없다.
- 자체 세션 인증이며 OIDC·OAuth·JWT Resource Server를 구현한 것으로 소개하지 않는다.
- OpenAPI의 제품 조회 스키마는 기존 문서에 있고, 인증·비교의 구체적 계약은 이 문서를 기준으로 한다. 자동 생성·동기화된 통합 명세는 후속 보완 대상이다.
