# 가격 자동 갱신 — 로컬 개발 연동

## 구현 범위

기존 MySQL 제품 카탈로그에서 가격만 외부 조회 값으로 갱신한다. 제품 사양·이미지·사용자 계정·취향·저장된 비교 스냅샷은 변경하지 않는다. 가격 이력 그래프·관심 제품·목표가 알림·상품 관리 기능은 이번 범위가 아니다.

공식 쇼핑 API의 인증된 가격 응답을 사용한 구현은 아니다. 다나와 공개 상품 HTML의 JSON-LD `Product.offers.lowPrice`를 읽는 개발용 연동이다. 공개 서비스 사용 승인이나 데이터 재표시 권한을 획득한 상태는 아니다.

## 데이터 흐름

1. 서버가 기존 `priceComparisonUrl`을 읽는다.
2. `https://prod.danawa.com/info/?pcode=숫자` 형식만 허용한다. 사용자 입력 URL을 받는 수집 API는 추가하지 않는다.
3. HTML의 JSON-LD에서 URL의 제품 번호와 `Product.sku`가 같은 제품 하나를 찾는다.
4. 원화 AggregateOffer이며 판매 제안이 있고, 최저가가 양의 정수일 때만 반영한다. 누락·중복·다른 통화·0원·잘못된 제품 번호는 거부한다.
5. MySQL의 가격·확인일·정상 수신 시각·갱신 상태를 저장한다. 가격이 이전과 같아도 정상 조회 시각은 갱신한다.
6. 기존 `/api/v1/products`와 `/api/v1/products/{id}`에서 최신 DB 값과 메타데이터를 제공한다.
7. Flutter가 카탈로그를 다시 받으면 탐색·추천·비교와 열린 상세·가격 화면에 반영한다. 비교 중 선택한 제품은 유지한다.

조회 값은 해당 페이지가 제공한 최저가이며 결제 확정 가격이 아니다. 배송비·카드·쿠폰·색상·옵션 조건은 판매 페이지에서 확인한다.

## 갱신 주기와 실패 처리

- 서버 시작 30초 뒤 첫 작업을 실행한다.
- 작업은 1분마다 실행 대상을 확인하되, 같은 제품의 실제 외부 조회는 최소 1시간 간격이다.
- 한 번에 최대 20개이며 요청 사이에는 2초 간격을 둔다. 현재 등록 제품은 20개이다.
- 연결 제한은 5초, 응답 본문 수신을 포함한 전체 대기는 12초이다.
- 자동 리다이렉트를 따라가지 않는다. 403·429는 우회하지 않고 공급자 수집을 1시간 중단한다.
- 실패 시 가격·마지막 정상 조회 시각·확인일을 덮어쓰지 않는다. 마지막 시도 시각과 실패 상태만 갱신한다.
- 앱은 최초 실행, 포그라운드 복귀, 사용 중 5분 간격으로 서버 카탈로그를 다시 받는다. 외부 사이트를 앱에서 직접 호출하지 않는다.
- 앱이 백그라운드로 가거나 AppShell이 제거되면 주기 타이머를 해제한다.
- 서버 연결 실패 시 기존 카탈로그 캐시와 데이터 수신 시각·재시도 흐름을 유지한다.

서버의 가격 갱신 주기와 앱의 카탈로그 수신 주기는 별개이다. 5분마다 페이지 가격을 수집하는 것이 아니다. 외부 페이지 자체의 캐시나 지연까지 제거하는 실시간 스트리밍도 아니다.

## API 추가 필드

기존 `price`·`priceCheckedAt` 필드는 유지한다. 가격 확인일은 마지막 정상 확인의 한국 날짜이다.

| 필드 | 의미 |
|---|---|
| `priceFetchedAt` | 자동 수집이 성공한 UTC 시각. 수동 확인만 했으면 null |
| `priceAttemptedAt` | 마지막 자동 수집 시도 UTC 시각 |
| `priceRefreshStatus` | `manual`: 수동 가격, `updated`: 최근 자동 조회 성공, `failed`: 최근 시도 실패 |

Flutter는 추가 필드가 없는 기존 응답·캐시·비교 스냅샷도 수동 확인 값으로 읽을 수 있다. 실패 상태에서는 실제 마지막 확인 시각과 ‘갱신 지연’을 함께 보여준다. 카탈로그의 ‘데이터 수신’ 시각은 외부 가격 확인 시각과 구분한다.

## DB·실행 설정

`V4__product_price_refresh.sql`은 제품 테이블에 메타데이터 컬럼만 추가한다. 적용된 V1~V3은 수정하지 않았다. 계정·비교 기록·MySQL 볼륨을 삭제하거나 새로 만들지 않는다.

개발용 `backend/compose.yaml`은 `PICKWISE_PRICE_REFRESH_ENABLED`를 기본 true로 전달한다. 코드의 기본값과 공개 배포용 Compose는 비활성이다. 단독 Spring Boot 실행에서 사용하려면 환경변수를 명시해야 한다. Flutter 실행 인자와 기존 기본 서버 주소는 변경하지 않는다.

```bash
cd backend
docker compose up -d --no-deps --build api
```

실행 중인 API가 있으면 이 명령은 API 컨테이너를 재생성한다. 짧은 연결 중단이 발생할 수 있다. MySQL은 재시작하지 않는다. 개발용 `.env`의 `PICKWISE_PRICE_REFRESH_ENABLED=false`로 자동 조회를 끌 수 있다.

## 검증 결과 — 2026-11-16

| 검증 | 결과 |
|---|---|
| Java 서버 전체 테스트 | 21개 통과. 실제 MySQL 테스트 DB 사용 |
| 외부 HTTP 실패 재현 | JVM 로컬 HTTP 서버로 성공·제품 불일치·302·403·429·500·시간 초과를 주입하고 실제 Java HTTP 클라이언트 실행 |
| DB 갱신 검증 | 정상 가격·메타데이터 반영, 중복 조회 제한, 실패 시 마지막 정상 값 보존, 공급자 차단 시 대기 확인 |
| Flutter 정적 분석 | 오류 없음 |
| Flutter 전체 회귀 테스트 | 170개 통과, LIVE_API_URL이 필요한 기존 실제 서버 테스트 4개는 기본 실행에서 제외 |
| 화면 추가 검증 | 가격·상세·비교의 좁은 화면과 확대 글자 등 관련 22개 테스트 통과 |
| Android | 디버그 APK 빌드 성공 |
| 실제 외부 수집 | 임시 8081 서버 → 다나와 → 실제 개발 MySQL → API 응답 확인. 첫 수집에서 20개 중 16개 성공, 4개 실패 |
| Docker | Compose 설정 검증 및 새 API 이미지 빌드 성공 |

최초 실제 수집 예시: WF-1000XM5 234,800원, AirPods Pro 3 227,990원. 문서 작성 시점의 조회 결과이며 이후 변할 수 있다.

최초 실패 제품은 C40i·P20i·P30i·P41i이다. C40i는 후속 공개 페이지 조회에서도 JSON-LD Product를 찾지 못했다. 나머지 세 제품은 Java 수집 시 통신 예외가 발생했고 별도 후속 HTTP 조회에서는 가격 데이터가 존재했다. 운영 파이프라인에서 실패한 값을 후속 점검 결과로 수동 덮어쓰지 않았다. 네 제품 모두 기존 정상 가격·확인일을 보존했다. 다음 정규 주기에서도 실패하면 계속 마지막 정상 값을 제공한다.

화면을 실제 시뮬레이터에서 조작하는 검증은 하지 않았다. Device Hub는 사용자가 직접 확인한다. Postman CLI 상태는 확인했으며 로그인된 워크스페이스가 없어 게시·계정 연결은 하지 않았다. 외부 장애 재현은 기존 Java 테스트 환경에서 로컬 HTTP 서버로 수행했고 Postman Simulation 실행 결과로 주장하지 않는다.

## 현재 실행 서버 적용 상태

사용자의 API 재생성 승인을 받은 뒤 `docker compose up -d --no-deps api`로 새 이미지를 8080 서버에 적용했다. MySQL은 기존 컨테이너 ID를 유지했고 healthy 상태이다. 계정·비교 기록·볼륨의 삭제나 초기화는 하지 않았다. 임시 8081 검증 서버는 종료했다.

적용 후 `/health`의 UP, 제품 목록 20개, 개별 제품 응답과 추가 메타데이터 필드를 실제 HTTP로 확인했다. 자동 갱신 환경변수는 true이다. 적용 확인 시 정상 갱신 16개·갱신 실패 후 이전 가격 보존 4개였으며, WF-1000XM5는 234,800원과 정상 조회 시각을 반환했다. 이미 조회한 제품은 재시작하더라도 DB의 최근 시도 시각을 기준으로 1시간이 지나야 다시 수집한다. Flutter 실행 주소·실행 인자를 변경할 필요는 없다. 앱 코드 반영은 Hot Restart 또는 재실행으로 확인한다. 시뮬레이터 직접 조작은 수행하지 않았다.

## 공개 운영 전 확인할 사항

- [다나와 정책 안내](https://www.danawa.com/info/agreement.html)는 콘텐츠 이용 조건을 별도로 안내한다. 공개 페이지에 접근할 수 있다는 사실과 자동 수집·앱 내 재표시 허용은 다르다. 공개 운영 전 승인된 공급 경로와 이용 조건을 확정한다.
- robots.txt는 접근 경로 확인 자료이며 이용 허락의 대체가 아니다. `/api/`, `/bridge/`, `/info/ajax/` 등 제한 경로는 사용하지 않는다.
- [다나와 MCP 문서](https://mcp.ai.cowave.kr/docs)의 접속 제한을 우회하거나 ChatGPT·Claude 커넥터를 우리 서버의 가격 공급 API처럼 사용하지 않는다.
- HTML 구조 변경이나 차단으로 수집이 중단될 수 있다. 현재는 기존 가격 보존과 갱신 지연 표시로 처리한다. 전체 상품 수집 성공을 보장하지 않는다.
- 다중 서버 운영 시 공급자 전체의 호출 제한과 수집 중단 상태를 공유하는 별도 작업 관리가 필요하다. 현재 개발 환경은 API 한 인스턴스를 기준으로 한다.
