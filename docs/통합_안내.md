# PickWise

사용자가 중요하게 생각하는 기준으로 이어폰을 탐색하고 비교하는 Flutter 앱입니다.

## MVP 기능과 구조

- 홈에서 제품 탐색 또는 취향 설정을 시작합니다.
- 탐색에서 브랜드·모델명 검색, 용도 태그 필터와 가격순 정렬을 사용합니다.
- 예산·착용 형태와 우선순위를 입력해 추천 결과와 근거를 확인합니다.
- 최대 3개 제품을 비교하고 각 제품의 상세·가격 확인 화면으로 이동합니다.
- 제품별 다나와 링크를 외부 브라우저로 엽니다.
- 비교 목록은 SharedPreferences에 저장·복원합니다.

제품은 `ProductRepository`가 JSON에서 읽고 `ProductProvider` 하나가 모든 화면에서 공유합니다. 홈·탐색·비교는 `AppShell`의 IndexedStack으로 유지하고, 취향·추천·상세·가격 화면은 Navigator.push/pop으로 이동합니다. 서버·로그인·결제·실시간 가격 수집은 MVP 범위에 포함하지 않습니다.

하단 메뉴는 Material `NavigationBar`를 사용하며 시스템 하단 여백을 제외한 높이는 64px입니다. 선택 표시는 220ms 동안 전환되고 홈·탐색·비교의 검색어와 스크롤 위치는 유지합니다. 기본 탭에서 세로 드래그가 24px 누적되면 읽는 방향에 따라 숨거나 다시 나타납니다. 가로 스크롤·코드로 이동한 스크롤에는 반응하지 않고, 탭 변경·비교 제품 수 변경 시 다시 표시합니다. 검색 키보드가 열리면 숨깁니다. 접근성 탐색에서는 자동 숨김을 사용하지 않고 모션 감소 설정에서는 전환 시간을 0으로 처리합니다. 상세·가격·추천 화면의 하단 메뉴와 상세 가격 확인 버튼은 스크롤로 숨기지 않습니다.

## 데이터 범위

앱은 `assets/data/products.json`의 실제 20개 모델과 로컬 사진을 사용합니다. 가격은 2026-11-03 확인한 다나와 제품별 페이지의 스냅샷이며 실시간 가격이 아닙니다. 배송비·혜택가와 실제 결제금액은 구매 페이지에서 확인합니다. 모델별 목록, 사양 확인 범위와 누락 항목은 [카탈로그 확장 및 검증](카탈로그_확장_검증.md)에 정리했습니다.

팀원 브랜치의 30개 초안은 `test/fixtures/catalog_draft.json`에 보존했습니다. 이 중 27개는 임시 데이터 표시가 있고 링크·가격 확인일이 누락되어 운영 목록에서 제외했습니다. 초안은 앱에서 읽지 않습니다. 이미지가 없거나 읽기에 실패하면 기존 이어폰 SVG를 표시합니다.

## 추천 계산 기준

1. 예산과 착용 형태를 먼저 필터링합니다. 선택하지 않은 조건은 제한하지 않습니다.
2. ANC 필수·한 쪽 무게 상한을 적용합니다. 제한을 만족하는지 확인할 정보가 없는 제품도 제외합니다.
3. 선택한 기준의 고정 범위 점수에 중요도(1~5, 기본 3)를 곱해 합산합니다. 누락된 사양에는 점수를 부여하지 않습니다.
4. 점수가 같으면 낮은 가격순, 가격도 같으면 제품 ID순으로 정렬합니다.
5. 최대 3개 후보와 JSON 사양을 근거로 한 설명을 표시합니다. 일치 제품이 없으면 조건별 제외 원인을 표시합니다.

후보 수에 따라 점수가 극단적으로 바뀌지 않도록 고정 범위를 사용합니다. 배터리 0~12시간(ANC 켬 값을 우선 사용하고 ANC 미지원 제품은 일반 재생), 한 쪽 무게 2~12g, ANC 지원 여부, IP 등급의 방수 숫자 0~8을 0~1로 환산합니다. 재생 조건은 화면과 추천 이유에 표시합니다. 가벼울수록 무게 점수가 높고 범위 밖 점수는 제한합니다. 중요도는 취향 설정과 추천 결과에서 조절할 수 있고 추천 순위·변경 이유에 즉시 반영합니다. 고정 범위와 가중 합산은 앱의 정책이며 실제 음질·착용감 평가를 대신하지 않습니다. 기준을 선택하지 않으면 낮은 가격순입니다. 귀걸이형은 `earHook` 고정 구조를 확인하므로 오픈이어형과 중복될 수 있습니다.

취향 설정의 조건·중요도는 `ProductProvider.selectionPreferences`로 공유하고, 비교 화면은 그 기준으로 장점과 다른 제품에서 유리한 점을 함께 설명합니다. 기존 비교 목록은 조건을 바꿔도 보존하며 새 조건과 어긋나는 제품을 표시합니다. 자세한 연결 계약과 검증 범위는 [의사결정 개선 1~3순위](의사결정_개선_1-3순위.md)에 정리했습니다.

## 실행과 검증

```bash
flutter pub get
flutter run
```

```bash
dart format --output=none --set-exit-if-changed lib test
flutter analyze
flutter test --no-pub
flutter build apk --debug --no-pub
```

테스트는 홈·검색, 취향 선택, 비교·상세·가격, 카탈로그, 전체 화면 이동으로 나눕니다. 통합 테스트는 선택 목록 저장·복원, 최대 3개 제한, 추천 조건, 빈 상태, 320px 화면과 키보드 표시를 확인합니다. 실제 기기에서의 외부 링크 실행은 별도로 확인해야 합니다.

## 협업 규칙

- 각자 담당 브랜치에서 작업하고 main에 직접 커밋하지 않습니다.
- 한 커밋에는 한 가지 목적을 담고 `종류: 변경한 내용` 형식으로 작성합니다.
- PR에는 변경한 기능과 확인 방법을 적습니다. 화면 변경은 스크린샷을 첨부할 수 있습니다.
- 분석·테스트와 주요 화면 흐름을 확인하고 팀원 1명이 검토한 뒤 병합합니다.
- 브랜치 전환 전에 미커밋 작업을 커밋하거나 임시 보관합니다. 의존성이 바뀌면 flutter pub get을 실행합니다.
- build/, API 키, 비밀번호, 개인정보는 커밋하지 않습니다.
