# PickWise 반응형 UI 수정 및 검증

검증일: 2026-11-16

## 수정 범위

기존 색상·로고·Provider 구조를 유지했다. 글자 크기를 강제로 줄이거나 시스템 글자 확대를 제한하지 않고, 콘텐츠에 맞게 높이를 늘리거나 배치를 전환했다.

| 화면·파일 | 수정 내용 |
| --- | --- |
| `home_screen.dart` | 제품 카드의 고정 높이를 제거하고 내용에 따라 늘어나게 변경했다. 가로 카드 높이는 서로 맞추고 제품 이미지 영역은 유지했다. 긴 브랜드·제품명은 목록에서 생략하고 상세 화면에서 확인할 수 있다. 가격은 줄 수로 제한하지 않는다. |
| `product_detail_screen.dart` | 사양 카드와 안내 영역을 최소 높이 기준으로 변경했다. 좁은 화면에서 글자가 커지면 주요 사양을 세로로 배치한다. 사양과 안내 문구의 한 줄 제한·축소를 제거하고 사양 텍스트를 가운데 정렬했다. |
| `liking_screen.dart` | 고정 높이 그리드를 내용에 맞게 늘어나는 선택 버튼으로 변경했다. 화면 폭·글자 크기에 따라 1열 또는 2열로 배치하며 체크 표시를 포함한 문구도 줄바꿈한다. 무게 드롭다운은 가용 폭 안에서 배치한다. |
| `importance_controls.dart` | 배터리 조건 드롭다운을 가용 폭 안에서 배치한다. |
| `product_comparison_screen.dart` | 제품명의 고정 높이를 제거하고 최대 두 줄을 사용한다. 제품 헤더와 사양 표의 좌우 여백을 일치시켰다. 높이가 부족한 화면에서 빈 비교 안내를 스크롤할 수 있게 했다. |
| `login_screen.dart` | 초기 화면의 ‘로그인 없이 둘러보기’ 문구가 아이콘과 겹치지 않도록 줄바꿈을 허용했다. |
| `main.dart` | 입력 안내·검증 오류를 최대 세 줄까지 표시해 큰 글자에서도 읽을 수 있게 했다. |

## 재현 및 회귀 테스트

`test/responsive_screens_test.dart`에서 실제 PickWise 앱의 테마를 읽어 버튼·입력창의 실제 스타일을 적용한다. 긴 제품명·브랜드·이메일·비교 기록 이름과 세 제품 비교 상태를 사용한다.

다음 12개 화면을 각 조건에서 검사한다.

홈, 탐색, 기준 선택, 추천 결과, 제품 비교, 제품 상세, 가격 확인, 마이페이지, 로그인, 회원가입, 비밀번호 변경, 저장한 비교.

크기는 Flutter 논리 픽셀 기준이다.

| 화면 크기 | 글자 배율 | 키보드 하단 점유 높이 |
| --- | --- | --- |
| 320 × 568 | 2.0 | 0 |
| 320 × 568 | 1.0 | 0 |
| 390 × 844 | 1.0 | 0 |
| 390 × 844 | 2.0 | 300 |
| 844 × 390 | 1.5 | 180 |
| 768 × 1024 | 2.0 | 0 |

세로 화면은 상단 47·하단 34, 가로 화면은 좌우 44·하단 21의 시스템 안전 여백도 모의 적용한다. 이 수치는 테스트 조건이며 모든 기기의 고정 여백으로 앱에 적용하지 않았다.

72개 화면·환경 조합에서 초기 배치와 스크롤 중 레이아웃 예외를 확인한다. 무게 드롭다운 열기·선택, 전체 사양 펼치기, 긴 이름의 저장 기록 열기도 확인한다. 인증 화면은 빈 입력 검증 후 오류 문구와 비밀번호 안내가 최대 줄 수 때문에 잘리지 않는지 추가 검사한다.

별도 네 테스트는 568 × 320 화면·글자 2배·키보드 높이 120 조건에서 홈·비교의 연결 오류와 빈 목록을 확인한다. 빈 비교 화면은 ‘제품 찾아보기’ 버튼까지 접근 가능한지도 검사한다.

`test/navigation_test.dart`는 홈 가로 카드가 실제로 스크롤된 뒤에도 하단 바의 위치·크기가 같은지 확인한다. 검색 입력창의 내부 스크롤과 혼동하지 않도록 제품 캐러셀을 지정한다.

## 최종 실행 결과

- `dart format`: 수정한 Dart 파일 포맷 완료.
- `flutter analyze`: 문제 없음.
- `flutter test --dart-define=LIVE_API_URL=http://localhost:8080`: 172개 통과. 반응형 76개와 기존 회귀·실제 Docker HTTP 테스트를 포함한다.
- `flutter build apk --debug`: 성공.
- `flutter build ios --simulator --debug`: 성공.

빌드 성공은 실제 기기에서의 모든 화면 동작을 보장하지 않는다. 위 반응형 검사는 Flutter 위젯 테스트 환경에서 수행했다. Device Hub나 시뮬레이터를 직접 조작하지 않았다.

## 시뮬레이터에서 확인할 내용

Hot Restart 후 로그인·회원가입에서 글자 크기를 키워 안내 문구와 오류 문구를 확인한다. 홈 카드·기준 선택·제품 상세를 스크롤하고 가로 회전한다. 비교표의 제품 헤더와 값의 정렬, 키보드를 열고 닫을 때의 화면 복원도 확인한다.

실제 OS 글꼴, 자동 완성, 키보드 애니메이션, 테스트 범위를 넘는 글자 배율과 기기 크기는 추가 실행 확인이 필요하다.
