# PickWise MVP 이후 기능 로드맵

## 범위와 목적

이 문서는 MVP 개발이 끝난 뒤 추가할 기능을 정리한다. 범위는 팀원 C가 맡은 **제품 비교(05) · 제품 상세(06) · 가격 확인(07)** 이다. 홈·탐색, 취향 설정, 추천 후보 선정과 추천 순위는 포함하지 않는다.

PickWise가 가격과 사양을 나열하는 데 그치지 않고, 사용자가 **차이를 이해하고 근거를 확인한 뒤 구매 시점을 판단하도록 돕는 것**을 목표로 한다. 다나와처럼 가격과 사양을 비교하는 서비스가 이미 있으므로, 단순히 비교 항목을 늘리는 것보다 정보의 근거·변화·구매 조건을 연결하는 데 우선순위를 둔다. [다나와 무선 이어폰 가격비교](https://prod.danawa.com/list/?cate=113838)

## 1. 비교 사양의 출처·확인일 바로 보기

### 사용자 문제

비교표의 숫자만으로는 사양이 제조사 공식 자료인지, 어떤 조건에서 측정된 값인지 알기 어렵다. 특히 배터리 재생 시간, 방수 등급, 무게처럼 조건과 표기 기준이 중요한 항목은 출처를 쉽게 확인할 수 있어야 한다.

### 기능 동작

- 비교표의 사양 값을 누르면 제품 상세의 해당 사양과 근거 링크로 이동한다.
- 상세 화면에서 출처 이름, 확인일, 원문 링크를 함께 보여준다.
- 수치 비교 시 조건이 다르면 같은 기준의 값처럼 합산하거나 우열 표시하지 않는다. 예: ANC 켬/끔, 이어버드 단독/케이스 포함 재생 시간.
- 공식 자료에 값이 없거나 제품 버전을 특정할 수 없으면 임의로 추정하지 않는다.

### 필요한 데이터와 완료 기준

- 각 사양에 `sourceUrl`, `checkedAt`, 측정 조건과 제품 버전이 연결되어야 한다.
- 비교표에서 값을 선택해 올바른 제품·사양의 출처를 열 수 있어야 한다.
- 링크가 없거나 확인일이 없는 값은 출처가 있는 것처럼 보이지 않아야 한다.

**차별화 포인트:** 비교 결과에 숫자만 제시하지 않고, 사용자가 핵심 차이의 근거까지 확인할 수 있게 한다. 제조사별 공식 비교 페이지도 사양을 나란히 보여주는 방식을 사용한다. [Apple AirPods 모델 비교](https://www.apple.com/airpods/compare/)

## 2. 가격 변동 그래프와 목표가 알림

### 사용자 문제

현재 가격 한 번만 보면 평소보다 비싼지, 최근 내려가는 중인지 알 수 없다. 목표 가격을 정하고 변동 시 알림을 받으면 구매 시점을 정하는 데 도움이 된다.

### 기능 동작

- 제품별 가격 확인 시점과 가격을 기록하고, 상세 화면에 기간별 가격 그래프를 보여준다.
- 사용자가 목표 가격을 설정하면 해당 가격 이하로 확인됐을 때 알림을 제공한다.
- 그래프에는 최저가·최고가와 조회 기간을 표시하고, 데이터가 부족한 기간은 선으로 보간하지 않는다.
- 가격을 비교할 때 판매처, 배송비 포함 여부, 제품 옵션이 같은 기록인지 구분한다.

### 필요한 데이터와 선행 조건

- 날짜별 가격 스냅샷을 누적할 저장소와 주기적 수집 방식이 필요하다.
- 알림을 보내려면 백그라운드 작업과 푸시 알림 서비스가 필요하다.
- 네이버·가격비교 사이트의 공식 API, 제휴 데이터 또는 허용된 수집 방법을 먼저 확인한다. 가격 이력과 알림 기능이 있는 서비스는 참고 사례일 뿐, 해당 데이터의 API 이용 가능성을 뜻하지 않는다. [N프라이스](https://www.nstoreprice.co.kr/)

### 완료 기준

- 가격 기록에 제품 식별자, 옵션, 판매처, 배송비 조건, 확인 시각이 저장된다.
- 목표 가격 알림은 같은 제품 옵션의 확인 가능한 가격에만 발송된다.
- 수집이 중단되거나 데이터가 오래되면 최신 가격인 것처럼 표시하지 않는다.

## 3. 비교 결과 저장·공유

### 사용자 문제

제품 비교는 한 번에 끝나지 않는 경우가 많다. 앱을 닫은 뒤 비교 조합을 다시 구성하거나, 화면을 캡처해 설명하는 번거로움이 있다.

### 기능 동작

- 현재 비교 중인 제품 조합을 이름을 붙여 저장한다.
- 공유용 요약에는 제품명, 확인된 가격, 주요 사양 차이, 가격·사양 확인일을 포함한다.
- 공유 화면에서 출처와 상세 화면으로 이어지는 링크를 제공한다.
- 공유 자료에도 기준일을 표시해 오래된 가격이 최신 정보로 오해되지 않게 한다.

### 필요한 데이터와 완료 기준

- 로그인 전 MVP 후속 단계에서는 기기 내 저장부터 검토한다.
- 링크 공유까지 지원하려면 앱 딥링크와 공유 대상에서 열리는 웹 또는 앱 화면이 필요하다.
- 저장한 비교 조합을 다시 열었을 때 삭제된 제품이나 변경된 사양을 구분한다.

## 4. 판매 옵션별 실제 결제 조건 비교

### 사용자 문제

상품의 표시 가격만으로는 배송비, 쿠폰, 색상·용량 옵션, 정품 여부를 포함한 실제 구매 조건을 알기 어렵다.

### 기능 동작

- 동일 모델의 판매 옵션을 식별한 뒤 판매처 가격과 배송비 등 확인 가능한 조건을 함께 보여준다.
- 판매처로 이동할 때 사용자가 선택한 모델·옵션과 맞는 상품 페이지를 연다.
- 조건을 확인할 수 없는 경우 최종 결제액으로 단정하지 않고, 판매처 페이지에서 확인하도록 안내한다.

### 필요한 데이터와 선행 조건

- 제품명 텍스트가 비슷한지만으로 동일 상품으로 처리하지 않는다. 모델 번호, 세대, 옵션을 대조한다.
- 가격·배송비·판매자 데이터를 제공하는 공식 API 또는 제휴 경로와 사용 조건을 확인한다.
- 데이터 접근이 불가능하면 판매처별 가격을 앱에서 임의로 구성하지 않고, 가격비교 페이지 이동을 유지한다.

**난이도가 높은 이유:** 색상·구성품·세대가 다른 상품을 잘못 묶으면 가격 비교 자체가 틀려진다. 동일 모델 식별과 가격 정보의 갱신을 먼저 해결해야 한다.

## 5. 제품군별 사양표 확장

### 사용자 문제

이어폰에 필요한 배터리·무게·방수 기준은 노트북이나 청소기 같은 다른 제품군의 비교 항목과 다르다. 모든 제품을 하나의 고정 사양표에 넣으면 빈 항목이 늘고 비교가 부정확해진다.

### 기능 동작

- 제품군마다 비교 항목과 표시 단위를 별도 정의한다.
- 제품 상세와 비교표는 공통 제품 정보와 제품군별 사양을 조합해 표시한다.
- 사양이 없는 제품은 임의의 기본값으로 채우지 않는다.
- 새 제품군은 데이터 구조, 상세 화면, 비교표를 함께 설계한 뒤 추가한다.

### 완료 기준

- 서로 다른 제품군의 무관한 수치를 같은 축에서 비교하지 않는다.
- 항목명, 단위, 비교 가능 여부가 제품군 설정으로 관리된다.
- 기존 이어폰 데이터와 화면이 그대로 동작하는지 확인한 뒤 새 제품군을 공개한다.

## 추천 개발 순서

1. **출처·확인일 연결을 완성한다.** 현재 JSON에 있는 출처 정보를 비교표까지 이어 사용한다.
2. **가격 데이터 제공 경로를 검증한다.** API·제휴 조건, 제품 식별, 가격 갱신 주기부터 확인한다.
3. **가격 이력을 쌓는다.** 알림보다 먼저 신뢰할 수 있는 기록과 그래프를 만든다.
4. **비교 저장·공유를 추가한다.** 로컬 저장부터 시작하고 링크 공유는 딥링크 준비 후 진행한다.
5. **판매 옵션과 새 제품군은 데이터 정확성이 확보된 뒤 확장한다.**

## MVP 이후에도 지킬 기준

- 기능을 추가하기 전에 “제품 비교·상세·가격 확인의 정확성이나 사용성을 실제로 높이는가?”를 확인한다.
- 외부 API는 문서만 보고 가정하지 말고, 응답 필드·호출 제한·이용 조건을 실제로 검증한다.
- 사용자에게 보이는 가격과 사양에는 출처와 확인 시점을 연결한다.
- 근거가 없거나 서로 다른 조건의 값은 정확한 비교처럼 표현하지 않는다.
- 사용자 취향을 입력받아 추천하거나 후보를 정렬하는 기능은 팀원 B 범위이므로 이 문서에서 구현 대상으로 삼지 않는다.
